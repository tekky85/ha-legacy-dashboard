# HA Legacy Dashboard 1.0.0-rc.8 – Public Test Release

Focused fix for [Issue #5](https://github.com/tekky85/ha-legacy-dashboard/issues/5).
This is not a final or stable release; `latest` remains unchanged.

## Saving larger dashboards

There was no 20-widget/entity limit. Admin sends the complete configuration,
including all dashboards, layouts, Room entities and rules. A global 16 KiB
JSON parser incorrectly rejected that batch with HTTP 413. Depending on the
configuration this looked like a limit around the 21st card or Room entity.

Authenticated Admin JSON now defaults to **1 MiB (1048576 bytes)**. Configure
`admin_config_max_bytes` in Home Assistant App options, or
`ADMIN_CONFIG_MAX_BYTES` for Standalone/LXC. Allowed range: **16384–16777216
bytes**; restart after changing it. The setting is a bounded byte budget, not
a per-dashboard entity count. The separate Room list validation (64 entities
per list) and finite grid dimensions remain unchanged.

Authentication and Admin write rate limiting happen before JSON parsing.
Light/Climate commands retain their small 16 KiB cap; secure image uploads
keep their independent validation/limit. Invalid/oversized requests cannot
replace the last valid configuration or its backup.

## Update without rebuilding dashboards

1. Back up the App including `/data` (Standalone: configuration, assets and `.env`).
2. Update to RC.8 and restart. Do not uninstall the App, clear `/data`, or remove
   cards to work around the previous limit.
3. Existing configuration/schema is unchanged and loads normally. Open Admin,
   confirm existing dashboards/Room Cards, add the previously failing entries
   and save. Reopen Admin and check after restart.
4. If an earlier failed save was never persisted, those unsaved edits cannot be
   restored by this update. Only previously saved data is guaranteed retained.

## Security and validation

Compatible backend dependency updates resolve the known production audit
findings, without weakening the audit. Regressions cover 60 cards, Room Cards
with 20/21/64 entities, byte boundaries, Unicode/gzip, preservation, restart,
authorization, rate limiting and the existing binary image path. CI uses only
local fake HA/Supervisor services, never real credentials.

HA/Supervisor tokens stay backend-only. No generic service proxy, extra HA
writes or App permissions were added. Safari iOS 9 / ES5 remains supported.
The independent Community Test-Center remains at
https://tekky85.github.io/ha-legacy-dashboard/testing/.
