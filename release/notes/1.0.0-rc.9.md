# HA Legacy Dashboard 1.0.0-rc.9 – Public Test Release

Community hotfix for [reports #8](https://github.com/tekky85/ha-legacy-dashboard/issues/8)
and [#9](https://github.com/tekky85/ha-legacy-dashboard/issues/9).
This is not a final or stable release. `latest` and all earlier RC artifacts
remain unchanged. This release includes the RC.8 Admin save-limit fix.

## Was wurde korrigiert?

- **Thermostat Minus/Plus:** Die serverseitige Prüfung verlangte bisher immer
  eine explizite `target_temp_step`. [Home Assistant darf diese Angabe weglassen](https://developers.home-assistant.io/docs/core/entity/climate/).
  Fehlt sie oder ist sie null, gilt jetzt wie in der bestehenden Bedienoberfläche
  die Schrittweite 0,5. Explizite gültige Geräteschritte haben Vorrang; ungültige
  Schritte, fehlende Temperaturgrenzen oder fehlende Steuerfreigaben bleiben
  gesperrt. Änderungen im ausgeschalteten Zustand senden weiterhin nur den
  Temperaturbefehl und keinen Einschaltbefehl. Die konkreten Attribute des
  Community-Thermostats lagen nicht vor: Falls es weiter gesperrt bleibt,
  müssen seine Fähigkeiten/Steuerfreigabe separat geprüft werden.
- **Dashboard löschen:** Ein Bestätigungsdialog innerhalb der Verwaltung
  ersetzt den teilweise unterdrückten Browserdialog. Zusätzlich ersetzt eine
  Titeländerung nicht mehr den gerade angeklickten Aktionsknopf. Abbrechen
  entfernt nichts; bestätigtes Entfernen ändert den Entwurf. Danach ausdrücklich
  „Änderungen speichern“ wählen. Das Standard-/letzte Dashboard bleibt geschützt.
- **Raumkarten:** Textzeilen werden bei zu wenig Höhe nicht mehr aufeinander
  zusammengedrückt. Aufgeklappte Details bleiben scrollbar. Unveränderte Karten
  werden bei automatischer Aktualisierung nicht ersetzt; geänderte Raumwerte
  werden im vorhandenen Element aktualisiert. Hintergrund, Aufklappzustand,
  Scrollposition und unveränderte Tasten bleiben erhalten. Andere Kartentypen
  behalten ihr bisheriges Aktualisierungsverhalten.

## Sicher aktualisieren – ohne Dashboard-Rückbau

1. Vorher eine Sicherung inklusive App-Daten erstellen.
2. In Home Assistant das App-Repository aktualisieren und RC.9 als Update
   installieren. **Nicht deinstallieren**, keine Karten oder Räume löschen.
   Bestehendes `/data/dashboards.json`, Bilder und Schema 12 bleiben erhalten.
3. App neu starten. Verwaltung und Anzeige neu laden; Assetkennung 56 verhindert
   die Mischung alter/neuer Skripte. Tatsächlich installierte Version RC.9 prüfen.
4. Standalone/LXC: versioniertes Paket und `SHA256SUMS` verwenden. Gemäß
   mitgelieferter Upgradeanleitung vorhandene `.env`/Daten geschützt übernehmen
   und den Dienst neu starten; altes Release mit Sicherung für Rollback behalten.

## Validation and security

Regressions use localhost fake HA/Supervisor services and the actual frontend.
The browser comparison against immutable RC.8 reproduces missing-step denial,
Room replacement/overlap under modeled legacy flex sizing, and suppressed native
confirmation; the corrected path is separately asserted. This is not physical
iPad or real HAOS proof. The release workflow runs the full regression suite,
syntax/security/version gates, browser card matrix and focused hotfix browser
tests before publishing amd64/aarch64 images and the standalone bundle.

The compatible transitive security update to `follow-redirects` 1.16.2 resolves
GHSA-mrwp-f3q8-3g9p. The production audit still blocks moderate/high/critical
advisories; no exception or reduced severity gate is introduced.

No generic service proxy, new writable domain, browser HA/WebSocket access,
extra App permission or credential exposure. HA/Supervisor secrets stay backend-only.
Safari iOS 9 / ES5 remains the wall-display target. The independently hosted
Community Test-Center is unchanged by this App update.
